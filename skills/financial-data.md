# 财务数据获取与交叉验证规范

本规范适用于股价、历史行情、财务报表、估值、汇率、基金净值和组合计算。
它不能承诺任何来源永不出错，但必须让错误可发现、可追溯，并在关键数据未通过
核验时停止给出决策级结论。

**硬规则：先定义指标口径，再取数；每个关键数据必须来自两个独立来源；冲突、
过期、证券身份不明或口径不一致时，必须 fail closed，不得触发买卖动作。**

## 与金融插件协同

已安装 `public-equity-investing` 时，公开证券研究优先使用它的工作流：

| 任务 | 采用的工作流 |
|------|-------------|
| 来源台账、单位/币种/日期标准化、冲突保留 | `financials-normalizer` |
| 模型、估值、监控器的来源追溯与勾稽 | `model-audit-tieout` |
| 持仓、仓位、压力测试和行动建议 | `portfolio-risk-management` |

`investment-banking` 只用于并购、融资、资本市场、交易流程和投行模型，不用于
个人持仓或公开股票买卖判断。可以借鉴它的模型审计方法，但不得把它当成公开
证券研究的主路由。

专业数据插件（如 FactSet、LSEG、S&P Global、Daloopa、Quartr）只有在当前
会话中实际可调用并返回数据时才算可用；manifest 中列为可选依赖不等于已安装
或已连接。

## 数据准入状态

每个用于研究结论、估值或交易触发的数据点必须标记以下状态之一：

| 状态 | 含义 | 是否可用于决策 |
|------|------|:--------------:|
| `VERIFIED` | 证券、口径、日期一致，两个独立来源在容差内 | 是 |
| `STALE` | 数据超过该指标的新鲜度限制 | 否 |
| `CONFLICT` | 来源数值、口径或日期不能解释性对齐 | 否 |
| `MISSING` | 缺来源、缺字段或无法确认证券身份 | 否 |
| `MANUAL_OVERRIDE` | 用户提供并明确承担口径责任的覆盖值 | 仅人工复核 |

任何程序都不得把 `STALE`、`CONFLICT`、`MISSING` 静默替换为旧缓存或另一条
单源数据后继续触发买卖信号。旧缓存可以展示，但必须与行动计算隔离。

## 第零步：定义指标契约

取数前先写清楚：

| 字段 | 必填内容 |
|------|---------|
| 证券身份 | 公司/基金名称、ticker、交易所、share class、ISIN（如有） |
| 指标定义 | 例如“滚动52周不复权日K盘中最高价”，不能只写“52周高点” |
| 时间口径 | 截止日期、滚动窗口、财年/自然年、时区 |
| 价格口径 | 不复权/前复权/后复权，盘中高/收盘价/调整后收盘价 |
| 财务口径 | GAAP/Non-GAAP，单季/累计/TTM，归母/含少数股东 |
| 单位口径 | 原始单位、缩放倍数、币种、汇率日 |
| 新鲜度 | 当前价、日K、净值、财报、估值各自允许的最大滞后 |

未定义以上字段时，不得开始比较或计算。不得把未记录语义的行情字段直接当成
“52周高点”“PE”或“净值”；历史高低点应从明确复权参数的时间序列重新计算。

### 台股（台积电2330、联发科2454、大立光3008等）

| 优先级 | 来源 | URL | 获取方式 |
|--------|------|-----|---------|
| 1（主） | **FinMind API** | api.finmindtrade.com | `tools/twstock_data.py`（零依赖脚本，见下） |
| 2（副） | **Goodinfo台湾股市资讯网** | goodinfo.tw/tw/StockDetail.asp?STOCK_ID={代码} | 直接访问 |
| 原始一手 | 公开资讯观测站（MOPS） | mops.twse.com.tw | 财报原文/月营收公告 |

**FinMind 取数工具**（分析台股时优先调用，输出自带市值验算）：

```bash
python3 tools/twstock_data.py quote 2330        # 最新行情 + PER/PBR/殖利率 + 市值验算
python3 tools/twstock_data.py valuation 2330    # 估值指标 + PER一年区间 + 52周高低
python3 tools/twstock_data.py financials 2330   # 近5年年度核心财务（营收/毛利率/归母净利/EPS/ROE）
python3 tools/twstock_data.py revenue 2330      # 近13个月月营收及同比
python3 tools/twstock_data.py dividend 2330     # 近年股利政策（现金/股票股利、除息日）
python3 tools/twstock_data.py search 台積        # 搜索股票代码（注意台股名称为繁体）
```

台股特别注意：

1. **货币单位是新台币（TWD）**，与港币/人民币/美元混排时必须显式标注，跨市场对比先统一换算
2. **月营收是台股独有优势**：上市柜公司每月10日前强制披露上月营收，是跟踪基本面拐点最快的公开信号，earnings-review/thesis-tracker 类分析应优先利用（`revenue` 子命令）
3. FinMind 损益表为**单季值**，工具已自动加总为年度值；不足4季的年份会标注"仅前N季累计"
4. FinMind 未注册可直接用（有小时级限额）。注册后的 API token **只存本机、严禁提交到 git**，工具按优先级自动读取：①环境变量 `FINMIND_TOKEN`；②本地文件 `local/finmind_token.txt`（`local/` 已被 `.gitignore` 永久排除，把 token 单独一行写入该文件即可）。token 不得出现在报告、skill、commit 中
5. 交叉验证：FinMind 数值与 Goodinfo（或 macrotrends 上的 ADR，如 TSM）对照，误差规则同下；台积电等有 ADR 的公司注意 ADR 与台股原股的汇率/存托比率差异（1 TSM ADR = 5 股 2330）

## 执行规范

### 第一步：获取数据

对每个财务指标（收入、净利润、毛利率、经营现金流、资产负债率等），分别从**来源1**和**来源2**取数。

两个来源必须独立。以下情况不算双源：

1. 同一供应商的两个 API endpoint
2. 两个网页都转引同一家数据商
3. 搜索摘要与其原始网页
4. 公司公告与复制该公告数字的聚合站

至少保留一个一手或近一手来源：交易所/监管文件、公司公告、基金公司净值、
指数公司方法与数据。行情聚合站只能作为独立复核，不能覆盖原始文件的定义。

### 第二步：误差计算与标记

```
误差率 = |来源1数值 - 来源2数值| / 来源1数值 × 100%
```

| 指标 | 默认容差 | 超出后的处理 |
|------|---------|--------------|
| 交易所价格/历史高低点 | 一个最小报价单位 | `CONFLICT`，停止触发 |
| 同口径财报原值 | 单位标准化后应相等 | `CONFLICT`，回到原始财报 |
| 同输入的派生计算 | Decimal 精确重算后应相等 | `CONFLICT`，检查公式 |
| 汇率 | 5 bps，且汇率日一致 | `CONFLICT` 或改用同一基准日 |
| 同定义估值倍数 | 0.5% | 标记差异并检查价格时点/分母 |

过去通用的“1%/5%误差”只适合低精度聚合数据的初筛，不适合价格、历史高点、
净值或模型勾稽。**定义不同不是舍入误差**，不得用放宽容差让两者“通过”。

### 第三步：数据呈现格式

每个关键数据必须按以下格式标注：

```
收入：1,239亿元 ✅
  - macrotrends: 1,241亿元
  - stockanalysis: 1,237亿元
  - 误差: 0.3%
```

差异示例：
```
净利润：245亿元 ⚠️ 数据存在差异
  - macrotrends: 245亿元（GAAP）
  - stockanalysis: 278亿元（Non-GAAP）
  - 误差: 13.5% — 原因：会计口径不同（GAAP vs Non-GAAP）
```

---

## 常见差异原因（不一定是数据错误）

| 原因 | 说明 |
|------|------|
| GAAP vs Non-GAAP | 最常见，尤其是利润类数据 |
| 汇率换算 | 港币/人民币/美元换算时间点不同 |
| 财年定义 | 自然年 vs 财年（如苹果财年10月结束） |
| 合并口径 | 是否含少数股东权益 |
| 数据更新滞后 | 某平台尚未更新最新一期财报 |

---

## 特别规则

1. **未上市公司**（米哈游、莉莉丝等）：只有一手数据来源时，数据前标记 `[估计]`，不执行交叉验证
2. **季度数据 vs 年度数据**：优先使用年度数据做交叉验证，季度数据部分来源可能有滞后
3. **原始财报优先**：若两个来源均与原始财报（10-K/年报PDF）不符，以原始财报为准，标记来源错误

## 股价与复权（历史序列必读）

价格有三种口径，混用会让历史股价位置、长期涨幅、历史估值分位全部失真：

| 口径 | 含义 | 用途 |
|------|------|------|
| 不复权 | 实际成交价，除权除息日跳空 | 实际成交点位、挂单价、滚动52周盘中高低点 |
| 前复权 | 以最新价为基准回调历史价 | 连续图表、拆分送转后的价格趋势比较 |
| 后复权/总回报 | 将分红送转纳入累计回报 | 总回报、年化收益、长期回撤 |

规则：

1. 不存在“所有历史价格统一前复权”。必须由指标契约决定口径，并在输出中显示。
2. 价格触发和“从实际盘中高点回撤”必须用**不复权盘中高价序列**；不能读取语义未确认的 quote 字段代替。
3. 总回报/年化收益必须使用总回报序列或明确计入分红，只看不复权价格会低估。
4. 历史 PE band 的价格与每股分母必须使用同一复权基础，不能只调整一边。
5. 跨越拆股/送转的历史每股指标必须同步复权，且记录 corporate action。
6. 当前市值用当前实际股价 × 当前股本，并用 `financial_rigor.py verify-market-cap` 验算。

## 程序化监控的额外要求

1. 对关键字段保存 `source_id`、URL/API、retrieved_at、as_of、currency、unit、
   adjustment、price_field、window 和 verification_status。
2. 主副来源必须分别保存原始值；冲突时不得只保留“最终值”。
3. 测试必须使用能区分语义的 fixture。例如 quote 字段为 9.156，但不复权日 K
   盘中高点为 9.305，测试必须断言系统选择 9.305。
4. 缺少双源核验、来源日期不一致或旧缓存没有验证标记时，输出
   `DATA_UNAVAILABLE`/`CONFLICT`，不计算交易触发。
5. 命令行输出必须显示价格/回撤来源和数据时间，便于人工复核。
6. 任何修改都要运行单元测试，并对至少一个真实标的做在线双源抽查。
